# P2：远程控制 + Web 控制台（2026-11-01）

> P3 起审批、核对、`approve` 权限和工单界面都已移除，见 [p3-notes](p3-notes.md)。下面保留 P2 当时的记录。

在 P1 的基础上加了一个远程入口：手机或浏览器可以看 Bot、聊天、新建 Bot、审批、打断、核对。

## 结构

```
浏览器 / 手机 ──HTTPS(tailscale serve)──► claude-2 127.0.0.1:7780 ──► pagentd 远程服务（remote.ts）
                                                                     ├─ 静态 Web 控制台（packages/web）
                                                                     └─ /api/*：设备会话 token + 权限范围
本机 CLI ──unix socket──► pagentd 管理 API（api.ts）：配对码、设备列表、撤销，以及 P1 的全部管理操作
```

- 远程服务**只发布到宿主 127.0.0.1**，局域网直接访问不到。
- 本机 API 和远程 API 共用 `service.ts` 里的操作：发消息（可选"打断并插话"）、审批、核对、Bot 状态、事件流。

## 设备认证（`devices.ts`）

1. 本机运行 `pagent device pair <设备名> [--scopes chat,approve,admin]`，生成 10 位配对码，5 分钟有效、只能用一次，库里只存它的哈希。
2. 设备用 WebCrypto 生成 **不可导出** 的 P-256 密钥对，只上传公钥；配对码经 CAS 消费。
3. 登录：服务器发一个一次性挑战，设备签名，服务器签发 12 小时的会话 token（库里只存哈希）。token 只放在 `Authorization` 头里，不出现在 URL 中。事件流用 fetch 读 SSE，而不是 EventSource，原因就是 EventSource 设不了请求头。
4. 撤销：`pagent device revoke <id>`。会话立即作废，该设备**正在连着的事件流也被服务端断开**。
5. 权限范围：`chat` 可以发消息、打断；`approve` 可以审批、核对；`admin` 可以新建 Bot、改人设和模型。**策略和插件只能在服务器 CLI 上改**，远程设备不行。
6. 其他防护：校验 Origin，跨站请求一律拒绝；严格 CSP，不允许内联脚本和内联样式；配对和登录失败有全局限流。

## Web 控制台（`packages/web`，零依赖）

视觉方向是"印章与工单"：

- 深松绿侧栏加近白工作区。每个 Bot 是一枚方印，印的是名字的第一个字。
- Bot 的回复像工作记录那样排版，左侧一条竖线，颜色和它的印章一致。
- 审批是一张带撕口的工单，撕口线上是真实的过期倒计时。
- 支持新建 Bot（名字可以用中文）、编辑人设和模型、置顶（存在设备本地）、搜索、"打断并发送"、停止、待处理页（审批和核对）。
- 手机宽度下，名单和对话分成两页，可以来回切换。
- 断线后自动重连，并按游标续传。

## 测试中发现并已修复

- SSE 要等第一个事件（或 15 秒一次的 ping）才会把响应头发出去，导致界面一直显示"离线"。现在一连上就先写一行数据，立刻能读。
- 一个头像形状的 SVG 路径写错了，画出来是空白。改风格时已经换掉。

## 还没做

- **手机访问需要 HTTPS**：浏览器只在 HTTPS 或 localhost 下才提供 WebCrypto。计划用 `tailscale serve` 给 127.0.0.1:7780 提供带有效证书的 HTTPS，这一步需要你登录自己的 tailnet。目前从 Mac 访问的方式是：

  ```bash
  ssh -N -L 7780:127.0.0.1:7780 claude-2
  ```

  然后打开 http://localhost:7780 。
- 置顶只存在本设备，不跨设备同步。没有推送通知（P5 用 APNs/FCM）。还没有"新建对话 / 历史对话"切换。
- CLI 配对时不显示二维码，只打印带 `#pair=` 的链接。
